1. INTRODUCTION TO REACT
=================================================================

What is React?

React is a JavaScript library used for building User Interfaces.

User Interface means anything the user can see:
- Buttons
- Forms
- Cards
- Navigation Bars
- Dashboards

Why is React popular?

Because it helps us build large applications by dividing them into small reusable pieces called components.

Real World Example:

Think of a house.

A house is made from:
- Doors
- Windows
- Rooms
- Kitchen

Similarly React applications are made from Components.

Interview Answer:
React is a JavaScript library developed by Meta for building reusable and dynamic user interfaces.

=================================================================
2. WHY REACT EXISTS
=================================================================

Before React:

Developers manually updated the DOM.

Example:

document.getElementById("title").innerHTML = "Hello";

For small projects this was fine.

For large projects:
- Difficult maintenance
- Repeated code
- Slow updates

React solves this using:
- Components
- Virtual DOM
- One Way Data Flow

=================================================================
3. VIRTUAL DOM
=================================================================

Most people memorize:

"Virtual DOM is a lightweight copy of the Real DOM."
But what does that actually mean?
Imagine a classroom of 100 students.
Only one student's marks change.
Will the teacher check all 100 students again?
No.
Only the changed student needs attention.
React follows the same idea.
When state changes:
Step 1:
React creates a new Virtual DOM.

Step 2:
Compares old and new Virtual DOM.

Step 3:
Finds differences.

Step 4:
Updates only changed parts.

Why important?

DOM operations are expensive.
React tries to do fewer of them.

=================================================================
4. REAL DOM VS VIRTUAL DOM
=================================================================

REAL DOM
- Actual browser structure
- Slow updates
- Directly changes screen

VIRTUAL DOM
- Exists in memory
- Faster comparisons
- Updates only changed nodes

Interview Question:

Why is React fast?

Because React uses Virtual DOM and Reconciliation to minimize DOM updates.

5. REACT RENDERING CYCLE
=================================================================

What is Rendering?

Displaying UI on screen.

What is Re-rendering?

Running the component again.

When does re-render happen?

1. State changes
2. Props change
3. Context changes
4. Parent re-renders

Important:

Re-render DOES NOT mean page refresh.

=================================================================
6. JSX
=================================================================

JSX = JavaScript XML

Allows us to write HTML-like syntax inside JavaScript.

Example:

const heading = <h1>Hello</h1>

Internally:

React.createElement("h1", null, "Hello")

Rules:

1. Single parent element
2. class becomes className
3. JS inside {}
4. Close all tags

=================================================================

What is a Component?

8. PROPS
=================================================================

Props allow Parent -> Child communication.

Example:

<User name="Nilesh" />

function User({name}){
 return <h1>{name}</h1>
}

Important:

Props are Read Only.

Never modify props directly.

9. STATE
=================================================================

Why do we need State?

Suppose:

let count = 0;

count changes.

Will UI update?

No.

React doesn't track normal variables.

State is React's special memory.

When state changes:
React updates the UI.

=================================================================
10. BATCHING
=================================================================

React groups multiple updates together.

Example:

setCount(count+1)
setCount(count+1)

Expected: +2

Actual: Often +1

Correct:

setCount(prev=>prev+1)
setCount(prev=>prev+1)

Now result becomes +2.

=================================================================
14. useEffect
=================================================================

One of the most important React topics.

What is a Side Effect?

Anything outside rendering.

Examples:
- API Calls
- Timers
- Event Listeners

Run Once:

useEffect(()=>{
 console.log("Mounted")
},[])

Run on dependency change:

useEffect(()=>{
 console.log(count)
},[count])

No dependency array:

Runs every render.

Cleanup Function:

Used to remove:
- Timers
- Event listeners

Common Mistake:

Infinite loops caused by wrong dependencies.

=================================================================
15. useRef
=================================================================

Stores values without re-rendering.

Example:

const inputRef = useRef();

inputRef.current.focus();

Use Cases:
- Focus inputs
- Store timer IDs
- Store previous values

=================================================================
16. useMemo
=================================================================

Problem:

Expensive calculations run again during re-renders.

Solution:

useMemo remembers previous value.

Think of it like caching.

Example:

const result = useMemo(()=>{
 return expensiveCalculation(num);
},[num])

=================================================================
17. useCallback
=================================================================

Functions are recreated every render.

useCallback remembers function references.

Example:

const handleClick = useCallback(()=>{
 console.log("Clicked")
},[])

Interview:

useMemo -> remembers value
useCallback -> remembers function

=================================================================
18. React.memo
=================================================================

Prevents unnecessary child re-renders.

If props don't change,
component doesn't re-render.

=================================================================
19. CONTROLLED VS UNCONTROLLED COMPONENTS
=================================================================

Controlled Component:

React controls input.

<input value={name}
 onChange={(e)=>setName(e.target.value)}
/>

Uncontrolled Component:

DOM controls input.

const ref = useRef();

<input ref={ref} />

Controlled is more common in React.
