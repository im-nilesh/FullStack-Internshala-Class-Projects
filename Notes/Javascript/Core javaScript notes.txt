Execution Context

in js there the memory exection is generaaly done in followiing step:

initially there is a global memoery allocation for all the variables that are defined in the program,
once the memory allocation is done the code execution starts and the variables recieve valuesfor those that
memory allocated

Whenever we are invoking any function, within the execution context therre is another exection context created,
that would be the local execution context for that function,
within this exection context there would be same 2 phases i.e 
Memory allocation phase and the other would be code exection phase.


There is a call stack present that has Global execution context at the end,
then the local execution context that are being called because of the functions get stacked up on the GEC 
once these local exection context are done with the memory allocation and the code execution they are popped off of the stack 
and at the end the GEC is executed.

Hoisting

We can access a variable in Js even before declaring the variable, this is known as hoisting.

for example:
    console.log(a);
    var a = 9;
    console.log(a);

    output for this block of code will be :
    undefined
    9

This is going to happen because during the execution context phase the memory is already been assigned to the variable about
in the program the value was not yet been declared for that variable and because of that we get undefined,
but later on we have provided a value of 9 that is why the output further shows us 9.

The above example was for variable hoisting,
the same can be applied for function hoisting too.

EVENT Bubbling and capturing

Event bubbling is basically, it basically runs the inner event then goes on top 
When an event happens on an element, it first runs on that element, then bubbles up to its parent, then grandparent, and so on until it reaches the document

Event Capture is when the outer element is handeled first then the inner event is handeled

as i said, the addEventListener takes 3 paramenters,
one is the event,
next is the function, third value is event capture which is a boolean value, if the value of this is false, event bubbling happens
if its true,
event capturing occurs

CallBack function :

The function that is passed as a paramenter to the higher order function is called as callback function

if the function is having a timeout, and the other function is dependent on the function which is having timeout, 
due to the timeout, the function cannot be accessed, and it returns undefined, 

to overcome this issue, callback functions are used so that the undefined doesnt happen

    setTimeout(()=> {
        const message = `Hello ${name}`

    },1000)
}

function displayMessage(message){

}

createMessage("Nilesh", displayMessage)

Promises (refer this entire topic from class or chatgpt) : 

Promise allows the program to continue with other tasks without waiting fot the Asynchronous operation to complete.
Once the asynchoronous task is comeplete the promise is fulfilled signaling the program that the data is ready for use

Create and consume promises

it requires the promise keyword, which takes a function, the function takes 2 callback functions one is resolve, 
other is reject

A Promise has 3 states:

Pending → still waiting

Resolved (fulfilled) → success

Rejected → failed



let myPromise = new Promise(function(resolve, reject) {

    let foodReady = true;

    if (foodReady) {
        resolve("Food is ready!");
    } else {
        reject("Food is not ready");
    }

});

myPromise
.then(function(result){
    console.log(result);
})
.catch(function(error){
    console.log(error);
});


.then() runs when the promise is fulfilled, 
.catch() runs when the promise fails

example 2:
let promise = new Promise(function(resolve, reject) {

    setTimeout(function(){
        resolve("Task completed");
    }, 2000);

});

promise.then(function(result){
    console.log(result);
});
